คนละงานกัน
คนละชั้นการป้องกัน

Anti-xray แบบดั้งเดิมออกแบบมาเพื่อทำให้ตำแหน่งแร่คาดเดาไม่ได้ แต่ไม่ได้มีหน้าที่ซ่อนฐาน ไอเท็ม หรือม็อบ ตารางนี้จึงเทียบ “สิ่งที่ข้อมูลรั่วได้” ไม่ใช่คะแนนความเร็วแบบรวม

เปรียบเทียบกับ anti-xray engine ที่เน้นการแทนแร่โดยเฉพาะ (รวมถึง built-in ของ Paper) ไม่ได้ตัดสินปลั๊กอินเจ้าอื่น และไม่ใช้ตัวเลขจากคู่แข่งที่ไม่ได้ตรวจสอบเอง

คำถามที่พบบ่อย

เรื่องที่คนถามก่อนติดตั้ง

ต่างจาก anti-xray ของ Paper อย่างไร?

Paper anti-xray ทำงานกับ แร่และบล็อกที่กำหนด ใน chunk เป็นหลัก แต่ Aegishider เป็น visibility gate ที่ตัด block entity, บล็อกฐาน, ห้องใต้ดินทั้งโวลุ่ม, ไอเท็ม และม็อบออกจาก packet ตามระยะ มุมมอง และ line of sight — และ re-hide เมื่อ chunk ถูกส่งซ้ำหรือไคลเอนต์ใช้ cache

ผู้เล่นจะเห็นหีบของตัวเองไหม?

เห็นเมื่อผ่าน policy: ภายใน 24 บล็อก และมี line of sight จริง ถ้าอยู่ในฐานของตัวเองและมองเห็นหีบ ก็เปิดใช้ได้ตามปกติ ส่วนผู้เล่นที่อยู่ผิวโลกจะไม่เห็นห้องใต้ดินเพราะ Y-shield

กิน TPS แค่ไหน?

งาน security ของปลั๊กอินเองวัดได้ p50 100–200 µs, p95 ≤0.85 ms, p99 ≤3.0 ms ต่อ tick และ MSPT delta เฉลี่ย +0.5–1.4 ms รวม overhead ของ PacketEvents ในชุดทดสอบ งานถูกจำกัดต่อ tick และเลื่อนได้โดยไม่ทำให้ข้อมูลโผล่

ใช้กับ ViaVersion ได้ไหม?

มี hotfix สำหรับกรณีไคลเอนต์ 26.x เชื่อมผ่าน ViaVersion ไปยังเซิร์ฟเวอร์ 1.21.4 โดย resolve block state ด้วย protocol ของเซิร์ฟเวอร์ และเวอร์ชัน 4.0.4 ถูกทดสอบสดบน Paper 1.21.11 (Java 21) และ Paper 26.3 (Java 25) — ควรทดสอบกับชุด ViaVersion ของคุณเองก่อน production

ฟรีจริงไหม มีเงื่อนไขอะไร?

ฟรี 100% ไม่มีระบบชำระเงิน ไม่มีกระเป๋าเงิน และไม่มีวันหมดอายุของใบอนุญาต สิ่งที่ต้องมีคือบัญชีฟรีสำหรับ activate เซิร์ฟเวอร์ และ PacketEvents 2.14.0+ สำหรับ block protection

เก็บข้อมูลอะไรบ้าง?

telemetry ของปลั๊กอินไม่ส่งชื่อผู้เล่น พิกัด หรือ IP ดิบ — เก็บเฉพาะข้อมูล operation แบบ aggregate และสถานะเซิร์ฟเวอร์ที่จำเป็นต่อการดูแลไลเซนส์/สุขภาพระบบ ส่วนแพลตฟอร์มอาจใช้ IP แบบ hash เพื่อ rate limit และป้องกัน abuse

ทำไมไม่รองรับ Folia?

เพราะ security path ต้องอ่าน world state และตัดสิน visibility อย่างสอดคล้องกันภายใน tick ปัจจุบัน การรองรับ Folia ต้องออกแบบ region-aware ใหม่ทั้งเส้นทาง ไม่ใช่แค่เปลี่ยน scheduler — เราเลือกไม่เคลมสิ่งที่ยังไม่ได้ทดสอบ
