# Aegishider 3.2.0 — Follow-up hardening (measurable improvements)

This document records the concrete improvements made after the 3.1.0 delivery, with the
measurements that justify them. It deliberately separates what was implemented, what was
tested automatically, and what was measured on a real Paper 1.21.4 server.

Version: **3.2.0** (build metadata only differs from the verified 3.1.0 behaviour in the
new subsystems below; the packet-protection core is unchanged).

---

## 1. Startup / first-player spikes

### What was changed
1. **Extended startup warm-up** (`AegishiderPlugin#warmupRuntimeOnce`):
   - still ray-traces from world spawn once worlds are available,
   - now also resolves **every configured protected material + filler** through
     PacketEvents' block-state registry for the server protocol version
     (`PacketMaterialCache#warmup`), so the lazy "loading block mappings" cost and first-use
     class loading are paid while no player is waiting for chunks,
   - touches the sanitizer/normalization class paths.
2. **BlockShield join ramp**: during the first 60 ticks after a viewer joins, candidate
   reveal checks are capped at 32/tick instead of 192/tick, spreading the join scan over
   more ticks (the shared tick/raycast budgets still bound it).

### Measured effect (real Paper 1.21.4, one headless client)
| Metric | 3.1.0 warm-up build | 3.2.0 | Comment |
|---|---|---|---|
| Block engine first-join max | ~38 ms | **~11 ms** | ramp + pre-warm |
| Item engine first-eval max | ~28 ms | ~31 ms | residual first reveal (`showEntity`/tracker classes); no player-path pre-warm possible without visible side effects |
| Server `/mspt` (300 items, 5 s window) | 3.5 / 1.3 / 8.6 ms | **3.1 / 1.2 / 8.0 ms** | steady state, single client |
| Aegishider tick p50/p95/p99 | 200 / 1000 / 3000 µs | 200 / 900 / 3200 µs | within noise; bounded |

Residual: one ~30 ms first-reveal spike per server session remains. It is a one-time
class-load/JIT cost; the tick budget and packet filter keep the security state correct
during it (the item simply stays hidden until the tick completes).

## 2. Item spawn-storm coalescing

### What was changed
- The per-tick item evaluation lane now switches to a **storm lane** when more than 64 items
  are pending: the batch is ordered **owner-visible first, then nearest-to-a-viewer first**
  (`ItemStormOrder`), and processed in that order. Far items are deferred to later ticks
  instead of monopolising the tick; gameplay-relevant items appear immediately.
- Removed a duplicated nearby-viewer-list/hash computation in the hot evaluation path
  (previously built twice per evaluated item).
- New metrics: `itemStormBatches`, `itemStormMaxDepth` (visible in `/aegishider diag` and the
  async diagnostics snapshot).

### Tests
- `ItemStormOrderTest` (4 tests): ordering, owner priority, empty/single batches.
- A datapack-driven 2,000-item burst in the load harness exercises the storm lane and its
  counters (results in §4).

## 3. Gateway watchdog + detected-position overflow alarm

### What was changed
- New pure `GatewayWatchdog` (unit-tested): if block protection is active and viewers are
  online but the gateway has processed **no** chunk/block packet for 5 minutes, one SEVERE
  log + admin alert is raised; the alarm rearms automatically when activity resumes. This
  catches "PacketEvents installed but broken/unregistered after an update" instead of it
  silently degrading.
- The packet-detected protected-position bridge (`DetectedProtectedBlocks`) has a
  configurable/testable bound; overflow is counted, logs SEVERE once per episode and raises
  an admin alert. Chunk data is still sanitized regardless (initial-data protection does not
  depend on the bridge).
- `/aegishider diag` now shows watchdog silence, detected pending/overflow, maintenance
  snapshot state and item-storm counters.

### Tests
- `GatewayWatchdogTest` (5 tests), `DetectedProtectedBlocksTest` (3 tests: drain, duplicate,
  overflow bound, minimum cap).

---

## 4. Bounded async pool now does real non-security work

### What was changed
- New `DiagnosticsSnapshot` (immutable, main-thread captured, 38 fields) and
  `DiagnosticsExporter`:
  - first snapshot 60 s after enable, then every 2 minutes,
  - JSON rendered on the main thread from immutable counters, **file write on the bounded
    async pool** (`plugins/Aegishider/diagnostics.json`, atomic replace),
  - `/aegishider export` triggers a snapshot on demand,
  - pool rejection increments a counter instead of silently dropping.
- Security decisions remain entirely main-thread; no visibility/entity work is offloaded.

### Verification
- `DiagnosticsExporterTest` (3 tests): JSON escaping/null, exact field count, atomic
  write/replace with no `.tmp` leftovers.
- Live server: `/aegishider export` produced a valid 837-byte `diagnostics.json`; diag showed
  `Async: submitted=... threads=4`; no errors.

## 6. What was intentionally NOT changed

- Player-vs-player visibility (needs team-aware policy) and 1.21.5+ chunk format support
  remain out of scope, as documented in the final report.
- Sound/particle effect filtering for container opening remains a documented residual gap.
- The packet-protection core (fail-closed chunk/block sanitization, ItemShield) was left
  untouched except for the hot-path allocation removal and storm ordering; the full E2E
  matrix must keep passing after these changes (see evidence).
